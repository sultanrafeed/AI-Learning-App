1Search: UCS · Greedy · A*Lecture 2↑ index
You walk a map. g(n) = cost already travelled to n. h(n) = a guess of the cost still to go. Each algorithm always expands the frontier node with the smallest score; they differ only in the score.
Spot it: graph, edge costs, h(n) under nodes, "expansion order", "path returned", "f(n) = ___".
AlgorithmScore (pick smallest)Frontier
BFSshallowest (oldest)FIFO queue
DFSdeepest (newest)LIFO stack
UCSf = g(n)priority queue
Greedy best-firstf = h(n) (ignores g)priority queue
A*f = g(n) + h(n)priority queue
  1. Table: Step | Expand (g, h, f) | Frontier after | Explored.
  2. Expand the smallest score. Add each neighbour with g_child = g_parent + edge cost and its score.
  3. Neighbour already on the frontier with a bigger g? Replace it with the cheaper one. Never re-add explored nodes (graph search).
  4. Tie → alphabetical (unless told otherwise). UCS / A*: stop when G is selected (popped), not when it is added. BFS: goal test when generated.
  5. Path cost = add every edge on the returned path.

Search problem = 6 parts: state space, initial state, goal test, actions(s), transition model RESULT(s,a), action cost c(s,a,s′). Assumes fully observable, deterministic, known → solution is a fixed action sequence. Romania: 20 cities, 20×20 0/1 adjacency matrix. Tree search may revisit states; graph search keeps an explored set.
2Admissible · consistent · propertiesLecture 2↑ index
Admissible = an honest optimist: the guess is never MORE than the real remaining cost. Consistent = the guess never drops by more than the step you just paid (a triangle rule on every edge).
Admissible: \(h(n) \le h^*(n)\)  ·  Consistent: \(h(n) \le c(n,n') + h(n')\) for every edge
  1. Admissible: compute the true cheapest cost h* from each node to G (run UCS backwards); compare.
  2. Consistent: check every edge in BOTH directions (edges are two-way). One failure → not consistent.
h(S)=16, edge S–B cost 6, h(B)=9: 16 > 6+9 = 15 → not consistent. Book 2: h(A)=7, h(D)=0, A–D cost 6: 7 > 6 → admissible (h*(A)=8) but not consistent. R→P: h(R) = 193 ≤ 97 + h(P) = 197 ✓. h(R) = 250 > true cost 198 → not admissible.

3Local search · simulated annealing · genetic algorithmLecture 3 · Week 3↑ index
Here the PATH doesn't matter, only the best final STATE (a schedule, a route, a queen layout). Start somewhere and keep improving by small changes.
Spot it: optimisation, objective/cost, neighbour, temperature, population, fitness, 8-queens tuple.
Formulate: decision variables x₁…xₙ (one set = one state) · cost Q(x) or fitness R(x) · objective min cost / max fitness · successor (neighbour) function · constraints lowᵢ ≤ xᵢ ≤ highᵢ. Delivery: state = route, neighbour = swap two stops, objective = min distance, constraint = visit each once and return. 20 stops → 20! ≈ 2.4×10¹⁸ routes. Continuous: min y = x² − 4x + 7 on [−2, 6] → (x−2)² + 3 → x = 2, y = 3.
8-queens state (x₁…x₈) = row of the queen in column i · cost = # attacking pairs · pair (i, j) attacks if \(x_i = x_j\) or \(|x_i - x_j| = j - i\)
cost(2,4,7,4,8,5,5,2) = 4 (rows: cols 1&8, 2&4, 6&7; diagonal: cols 3&8) · cost(2,4,6,8,3,1,7,5) = 0 · all in one row or one diagonal = 28 = C(8,2) · cost(1,3,5,7,2,4,6,8) = 1. Each state has 8×7 = 56 neighbours; 92 solutions, 12 fundamental. Hill climbing maximises f = −cost.
Hill climbing (steepest ascent): move to the BEST neighbour; stop when no neighbour is better. Stuck at local maxima, ridges, plateaus/shoulders → random restarts (also stochastic and first-choice variants; sideways moves cross plateaus).
y = x² − 4x + 7 from x = −1 (minimise): 12 → 7 → 4 → 3 at x = 2; neighbours 4, 4 → stop. 8-queens 24748552 (cost 4) → best of 56 neighbours 24748551 (cost 2). Values 10 with neighbours 8, 12, 15, 9 → move to 15.

High T explores (random walk); T → 0 = hill climbing. Cooling too fast → trapped like hill climbing; too slow → many iterations; sensitive to start T and schedule; runs differ; escapes local optima but NO guarantee of the global optimum in one run. Named after annealing metal; minimises "energy".
Roulette: \(P_i = f_i / \sum_j f_j\)  ·  Tournament k: pick k at random, fittest wins
f = 24, 23, 20, 11 (total 78) → P = 0.31, 0.29, 0.26, 0.14. Sorted cumulative: x4 [0,11) x3 [11,31) x2 [31,54) x1 [54,78] → randoms 15, 42, 51, 69 pick x3, x2, x2, x1 (same with 0.14/0.40/0.69/1.0 and 0.164, 0.416, 0.607, 0.894). Tournament k=3 on A70 B55 C40 D30 E20 F10: {A,C,E}→A, {B,D,F}→B, {C,D,E}→C.
Local beam search: keep the k best states, sharing information among them (stochastic beam: pick ∝ value). Evolutionary algorithms = stochastic beam + natural selection.
GA (Holland 1975): individual = chromosome (bit string) · selection (fitter more likely) → crossover (combine two parents: 110|01 + 001|11 → 110|11, 001|01) → mutation (flip a bit, keeps diversity) → elitism (copy the best). Factors: population size, representation, mixing number (parents, usually 2), selection, recombination, mutation rate, makeup of next generation. Bigger k = more selection pressure, less diversity. Tournament needs no normalising; fitness 0 can't be picked by roulette.
✗ Use the cumulative order the question gives. ✗ "SA guarantees the global optimum" = FALSE. ✗ Local search does NOT keep the path.
4Decision tree split: entropy · IG · GiniLecture 4 · step-by-step sheet↑ index
A good question (attribute) splits the examples into PURE groups. Entropy and Gini measure "mixed-up-ness": 0 = pure, max when 50/50. Information gain = how much mixed-up-ness the split removes.
Spot it: [6+, 6−] at the parent, branches with counts, "IG", "Gini", "which attribute is chosen".
\(H = -\sum_k p_k \log_2 p_k\)   \(\text{Gini} = 1 - \sum_k p_k^2\)
\(IG = H(\text{parent}) - \sum_v \frac{|S_v|}{|S|} H(S_v)\)   Gini reduction = Gini(parent) − Σ (|Sᵥ|/|S|)·Gini(Sᵥ)
  1. Parent: H and Gini.
  2. Each branch: H and Gini (pure → 0; 50/50 → H = 1, Gini = 0.5).
  3. Weight each by branch size ÷ parent size (not a plain average) and add.
  4. Subtract from the parent. Pick the highest IG = lowest weighted Gini.
